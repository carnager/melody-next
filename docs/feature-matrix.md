# Feature matrix

Last reconciled: 2026-10-06, through ADR-0274 -- database schema 53,
protocol 1 at level 8 ([protocol levels](protocol-levels.md)). The
application is Melody (`src/bench`, installed as `melody`), a client
of engines ([unified engine](unified-engine.md)): every library, list and
file it shows belongs to an engine -- this computer's or one elsewhere -- and
the engine does the work on them. Older ADRs speak of an MPD side and a local
side, or of authorities; that model is gone (ADRs 0220, 0224, 0234).

Use the [roadmap](roadmap.md) for implementation priorities and
[MILESTONES.md](../MILESTONES.md) for capability gates, the conditions for
1.0, and historical evidence. M5-M10 are complete; M11 (the unified engine)
is complete as ADR-0259 has it. Artifact-specific release acceptance remains
governed by the release checklist. An implemented feature does not by itself
close a milestone.

## Status vocabulary

- **Implemented:** available in the current workspace or the named core service,
  within the stated scope. This is not a claim that every related requirement
  or format is complete.
- **Partial:** usable implementation exists, with identified missing behavior.
- **Backend only:** reusable support exists without the complete current UI.
- **Open:** not implemented in the reviewed workspace.
- **Needs verification:** a source-review concern requires a regression test.
- **Deferred:** outside the immediate roadmap; proposals are not compatibility promises.

## Workspace and playlists

The list that plays is marked apart from the tab being browsed. Stop and
Pause keep that list; playing another moves the marker. Workspace offers a
persisted, opt-in Cursor follows playback toggle and Jump to playing
(Ctrl+J). A list another client changes follows here as edits (ADR-0256).

Diagnostic tracing is opt-in via `--debug` or explicit `QT_LOGGING_RULES`;
ordinary startup suppresses the `melody.debug` trace category while
retaining warnings and errors (covered by the `debug-log` regression test).

## Engines, libraries, and playback

The engine era (ADRs 0220–0236). Each engine owns its library, lists, queue,
playback, history and scrobbling; Melody, the Android app and `melody-cli`
are clients of it over protocol v1. The MPD client and everything built on it
-- MPD profiles, the live MPD queue, stored MPD playlists, server list tabs,
server-side search translation, MPD/local mapping -- were removed in
ADR-0224.

| Capability | Status | Current behavior and remaining work |
| --- | --- | --- |
| Engine (`melodyd`) | Implemented | One process owns catalogue, lists and playback and keeps playing with every client closed (ADR-0220). This computer's engine is systemd's on Linux -- `melodyd.socket`, enabled by the package, starts it on the first connection -- and Melody only connects; on macOS Melody starts it, as `melodyd` with no other flag (ADR-0286, tested in `engine-service`, `engine-launcher`); a headless engine runs anywhere. Melody's sharing settings are the engine's `melodyd.conf`, over `config.get`/`config.set`, handed over once and on every save (tested in `bench-main-window`, `sharingSettingsAreHandedToTheEngineOnce`). Stable engine id kept in its state directory (ADR-0234). Configured by `melodyd.conf` -- `key = value`, the options' names, comments and `[engine NAME]` sections, flags over it -- which `melody-cli config` reads, changes and `--edit`s, each change checked as melodyd reads it and the rest of the file kept; a new one starts from a commented skeleton of every setting, and the environment file of before is converted once (ADR-0286, tested in `config-file`, `daemon-settings`, `melody-cli-config`). | Capability | Status | Current behavior and remaining work |

| File work in the engine | Implemented | Reading, writing, ReplayGain, conversion and moves are done by the engine whose files they are, on its machine; the tagger and its tools look and work the same on every engine (ADR-0237). ## Format-support dimensions

Playback, text writing, artwork writing, ReplayGain storage, encoding, and
integrity verification are independent capabilities. FFmpeg availability alone
never qualifies a writer or proves exact seek/gapless behavior.

| Container | Qualified text mutation | Qualified artwork mutation | Qualified conversion output |
| --- | --- | --- | --- |
| Native FLAC | Yes | Yes | Yes |
| Native WavPack | Yes, within adapter restrictions | No | No |
| MP3 | Yes, qualified ID3 path | Yes, APIC qualified path (ADR-0137) | Yes |
| Ogg Vorbis | Yes, single-stream qualified path | No | Yes |
| Ogg Opus | Yes, single-stream qualified path | No | Yes |
| MP4/M4A (AAC/ALAC) | Yes, box-preserving qualified path (ADR-0136) | Yes, untyped covr qualified path (ADR-0137) | No |
| WAV/RF64/Wave64, AIFF, other decoded containers | No qualified writer | No | No qualified output preset |

Conversion outputs remain conditional on the installed FFmpeg encoder/muxer.
WavPack trailers and chained/multiplexed Ogg streams have explicit restrictions;
see [ADR-0095](adr/0095-prepared-copy-wavpack-text-writer.md) and
[ADR-0114](adr/0114-qualified-ogg-writers.md). Text mutation qualification does
not automatically qualify ReplayGain interoperability or logical-track writes.
Use the real fixtures and feature-specific specifications for exact claims.

Tabs distinguish browsing from playback: the selected tab has a lighter
background and accent underline; an accent speaker icon marks the list that
plays, including while paused or stopped. Titles use normal text color.

Edit tags opens the same editor for every engine's files; the engine they
belong to reads and writes them (ADR-0237).
